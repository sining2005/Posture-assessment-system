6. 候选骨盆/脊柱模型完成端到端验证，形成"模型输出 vs 几何代理指标"对比结论。
7. 用户信息 → 体态检测 → 骨盆检测真机全链路可用。

## 四、详细周计划

### 第 1 周：深度相机真机联调与采集环境就绪

**计划**：
1. 安装并初始化 Azure Kinect Sensor SDK / Body Tracking SDK，完成深度相机硬件自检、驱动与运行库验证。（✅ 已完成）
2. 联调现有 DepthCameraAdapter 真机路径，验证 RGB、深度、32 关节骨架数据流，排查原生 SDK 调用与工作进程问题。（✅ 已完成）
3. 完成地面标定与 IMU 重力标定档案建立，确认相机安装高度（约 1.2–1.4 m）、站位距离（1.8–2.2 m）与单人采集环境。（✅ 已完成，待现场规范化）
4. 用真机替换模拟/回放模式，跑通"启动采集→质量门→五姿势/四方向→MKV/NPZ/PNG 落盘→重拍归档"完整流程。
5. 记录真机运行日志：帧率、分辨率、各姿势耗时与主要报错，与模拟模式对比差异。

**实现目标**：
1. 深度相机真机数据流打通，设备自检与地面标定通过。
2. 体态检测五姿势与骨盆四方向真机采集流程完整可跑。
3. 真机数据可正确保存并支持回放复现。
4. 明确真机与模拟模式的差异及当前阻塞问题清单。
5. 首批真实数据开始采集，为第 2 周验证提供数据基础。

**交付物**：`真机运行日志.md`（帧率/分辨率/姿势耗时/报错表）、五姿势+四方向各 1 名受试者采集样例、阻塞问题清单。

### 第 2 周：真实数据验证与全链路联调

**计划**：
1. 使用真机采集 3–5 名受试者 ×（五姿势 + 骨盆四方向）数据，建立首批真实数据集并完成质量统计。
2. 用真实数据回归测试质量门阈值（单人、距离、深度/轮廓覆盖、28/32 关节、骨盆稳定度、朝向、Adams 前屈角）。
3. 验证骨盆指标（髋中心高低差、髋轴冠状倾斜、中心侧移、前后倾、水平旋转、体表对称差）在真机数据上的合理性、置信度与跨视图一致性。
4. 将候选骨盆/脊柱检测模型部署到运行环境，用真机采集图像跑通"输入图像→模型推理→输出检测或三维结果→保存文件"完整流程。
5. 对比候选模型输出与现有几何/代理指标，评估模型对体态检测与骨盆检测的增益与适用性。
6. 联调"新建患者→发起检测→真机采集→分析→查看结果"全链路，完善用户信息模块与会话交接。
7. 输出真机验证报告，明确模型可行性结论及下一阶段改进项。

**实现目标**：
1. 首批真实数据集入库，完成质量门通过率与异常原因统计。
2. 确认质量门与骨盆指标在真机场景下的准确度及需调整项。
3. 候选模型完成端到端验证，明确其可输出的骨盆/脊柱/骨架结果。
4. 形成"模型输出 vs 几何代理指标"对比结论，给出初步可行性判断。
5. 用户信息→体态检测→骨盆检测真机全链路可用。
6. 未达标项明确阻塞原因与下一步解决方案。

**交付物**：`首批真实数据集清单`、`真机验证报告.md`、模型对比初稿、全链路联调记录。

### 第 3 周：数据集扩充与质量门调优

**计划**：
1. 按机构伦理/隐私要求扩充至 20–30 名受试者，每名受试者完成五姿势+四方向，必要时重复采集。
2. 统计质量门通过率与失败原因分布（距离/多人/覆盖/关节/稳定度），定位系统性问题。
3. 回归质量门阈值：对通过/失败样本做敏感性分析，输出阈值调整建议（不改动的部分保持 `validated=false`）。
4. 建立数据标注与人工复核规范：量尺/角度/直线标注与体态师复核流程标准化。
5. 整理"真机 vs 模拟"差异清单：帧率、关节抖动、深度空洞、衣物伪影等在真机上的表现。

**实现目标**：数据集规模达标、质量门异常归因清晰、阈值调整有数据支撑、标注规范成文。

**交付物**：数据集统计报告、阈值回归表、标注规范文档。

### 第 4 周：模型部署与推理管线

**计划**：
1. 从候选模型（YOLO-Pose / RTMPose / MediaPipe / 骨盆专用分割模型等）中选定 2–3 个进入部署验证。
2. 本地/容器化部署推理服务，打通"真机 RGB/深度图 → 模型推理 → 骨架/骨盆/脊柱检测 → JSON/图像结果落盘"管线。
3. 对骨盆区域（四方向）建立 ROI 提取与模型输入预处理（对齐、缩放、归一化）。
4. 记录模型推理耗时、内存占用、硬件（GPU/CPU）依赖与失败场景。

**实现目标**：至少 2 个候选模型完成真机图像端到端推理并落盘。

**交付物**：模型推理管线代码、部署说明、推理结果样例。

### 第 5 周：模型 vs 几何指标对比评估

**计划**：
1. 在同一批真机数据上，同时计算现有几何/代理指标与模型输出指标。
2. 对比维度：骨盆关键点定位误差、脊柱侧弯/旋转趋势一致性、跨姿势稳定性、对衣物/遮挡的鲁棒性。
3. 以人工复核标注为参照，计算模型与几何指标的一致性（相关系数、偏差、检出率）。
4. 输出对比报告，给出"模型是否有增益、哪些指标值得替换/补充、需要哪些真实标注才能定级"的结论。

**实现目标**：形成正式可行性结论，明确下一阶段技术路线。

**交付物**：`模型对比评估报告.md`、对比数据表、可行性结论。

### 第 6 周：指标融合与分级体系

**计划**：
1. 基于第 5 周结论设计融合策略：模型指标（如可用）+ 几何代理指标 + 人工复核的优先级与权重。
2. 完善置信度体系：将模型置信度、深度覆盖、关节完整度、跨视图一致性纳入融合。
3. 输出分级规则草案（全部保持"实验性/待验证"），明确哪些指标可进入正式分级、哪些仍需验证。
4. 完成跨视图一致性判定与"需人工复核"触发逻辑在真机数据上的回归。

**实现目标**：融合算法落地、分级规则成文、置信度体系闭环。

**交付物**：融合算法代码、分级规则草案、回归结果。

### 第 7 周：报告与 UI 完善

**计划**：
1. 实现报告模块：从 `analysis_ready(session_id)` 结构化数据生成报告（首版为结构化展示，PDF 视需求）。
2. 完善查看结果页：五姿势/四方向叠加预览、指标解释、免责声明、实验性标记。
3. 完善采集页交互：真机实时预览、重拍提示、质量门失败原因可视化。
4. 用户信息模块与会话交接的全链路验收（新建→检测→分析→查看）。

**实现目标**：全链路界面可操作、报告可生成、免责声明完整。

**交付物**：报告模块、UI 改版、验收记录。

### 第 8 周：重复性验证

**计划**：
1. 按 README 目标设计重复测量实验：每名受试者每姿势至少 3 次采集。
2. 计算 ICC（目标 ≥ 0.90）、角度 MAE（≤ 2°）、距离 MAE（≤ 10 mm）、Adams 对测斜仪 MAE（≤ 2° 且 ICC ≥ 0.85）。
3. 对未达标指标保持"实验性"标记，记录改进方向（阈值、算法、采集规范）。
4. 输出验证报告与达标/未达标清单。

**实现目标**：重复性数据达标或明确未达标原因。

**交付物**：`重复性验证报告.md`、ICC/MAE 数据表。

### 第 9 周：性能优化与打包

**计划**：
1. 分析真机采集帧率瓶颈（DirectML/CPU、进程通信、存储 IO），针对性优化。
2. 验证长时间运行稳定性（连续采集多个会话、内存/临时文件清理、重拍归档）。
3. 制作部署包：依赖清单、SDK 放置说明、启动脚本、环境变量文档。
4. 模拟无相机/相机占用/断线等异常场景，验证降级与报错提示。

**实现目标**：性能达标、部署文档齐全、异常处理完善。

**交付物**：性能报告、部署包、安装与运维文档。

## 六、验收标准（沿用 README）

- 重复测量 ICC ≥ 0.90；常规角度 MAE ≤ 2°；距离 MAE ≤ 10 mm。
- Adams 对测斜仪 MAE ≤ 2° 且 ICC ≥ 0.85。
- 未达标指标仍保存数值，但继续标记"实验性/待验证"。
- 全部筛查结论不输出疾病概率、Cobb 角或诊断结论。
